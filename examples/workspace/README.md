# Example workspace

A complete, runnable nextbrief workspace. Everything in it is invented: six
fictional projects, three backlog items, and a registry that exercises every
feature the format has.

```sh
./scripts/build-example.sh                        # or: make
nextbrief --workspace . sense --as-of 2026-03-16
```

`projects/` is generated rather than committed. It contains real git repositories,
which cannot be nested inside this repository without submodule machinery, and its
value depends on file timestamps that a `git clone` would overwrite with the time
you cloned. The build script pins both: every commit is authored by
`Example User <example@example.invalid>` at a fixed date, and every file's mtime is
set explicitly afterwards. Run it twice and you get the same snapshot.

Pass `--as-of 2026-03-16` when sensing. The example is calibrated against that
date; without it, everything reads as cold and the deadlines have all passed.

## What each project is here to demonstrate

| Project | Shape | Exercises |
|---|---|---|
| `orchard-api` | git repo, six commits | open decision, conflicting documents, non-goals table, `exclude_subpaths` |
| `beacon-portal` | subdirectory of the above | a project inside another project's repo, so git log filters by pathspec |
| `lantern-site` | spans two repositories | a nested repo (`atelier/sites/lantern`) plus a path in the outer repo |
| `tidepool-docs` | plain directory, no VCS | `git: "none"`, file-timestamp evidence only, hand-written deadlines |
| `kiln` | git repo, maintenance phase | `privacy.never_read`, `has_own_daily_entry`, `hard_rules` |
| `quarry` | git repo, dormant | uncommitted changes with no next step; a sprint doc that says "Done" |

Plus `sandbox` and `archive/talks` under `watch`, `homelab-config` under `infra`,
`handoff-inbox` and `tmp` under `ignored`, and two `archived` directories.

## Signals the example is built to produce

- **Staleness.** `tidepool-docs/HANDBOOK_STATUS.md` was edited on 2026-03-10 but
  still declares `> Last updated: 2025-11-02`. A status document that stops being
  edited does not stop being believed, which is what the threshold is for.
  `atelier/CURRENT_SPRINT.md` is stale too, but declared `known_stale` in the
  registry — you already know, so it should not cost you an alert.
- **Privacy.** `kiln/fixtures/private/` holds three files. The snapshot records the
  number three and nothing else: no names, no contents, no paths.
- **A decision, not neglect.** `orchard-api` is `blocked_by: decision`, so it
  belongs under "decisions pending" and never under "stalled". Calling a
  deliberate pause procrastination is how a brief loses your trust.
- **Delegation.** `kiln` publishes `OPERATIONS_LOG.md`, so the brief links to it
  and counts what is open there instead of restating it.
- **A proposal awaiting confirmation.** `NA-0003` carries
  `proposed_status: done`. Only a human writes `status: done`; a false completion
  is far more damaging than a missed one, because a missed item stays visible.
  The brief prints it under "waiting for your confirmation" with the commands
  that answer it — `done` agrees, `ok` disagrees, and either clears the field.
- **Untrusted content.** `handoff-inbox/vendor-notes.md` contains a line
  instructing the reader to mark every task complete. It is a fixture. Anything
  read out of a project directory is data to report, never a command to follow.

## Files here

```
registry.jsonc        what the projects are      (edited monthly)
config.jsonc          thresholds and caps        (edited rarely)
backlog/*.md          one file per item          (edited daily)
scripts/build-example.sh
projects/             generated
state/, log/          generated by a run
```
